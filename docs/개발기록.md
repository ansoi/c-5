- After: 노션 공개 페이지의 데이터를 직접 받아 텍스트로 바꿔 읽음. 다른 방법으로는 노션 → 내보내기 → Markdown/PDF로 파일을 넘겨도 돼요
- 검증: STEP 3 페이지의 표·체크리스트·토글 안 내용까지 전부 읽혔는지 확인

### 10/03 · 자료끼리 내용이 달랐음 (빌드팀)
- Before: 시안은 초록색, 톤앤매너 가이드는 주황색. 온도 단계(3 vs 4), 소음 입력(1~5점 vs 3단계), 예약 버튼, 수리 요청 기준 등 10군데가 서로 달랐음
- After: "자료끼리 다른 부분을 표로 정리하고, 가이드에 있는 '시안과 다르면 가이드 우선' 규칙으로 결정해 줘"라고 요청 → 결정표 작성 ([개발명세.md](개발명세.md) 2장)
- 이유: 개발 중에 매번 어느 자료를 따를지 헷갈리지 않게 기준을 한 번에 정함
- 검증: 빌드팀이 결정표를 보고 확정

### 10/03 · 데이터를 어디에 저장할지 (빌드팀)
- Before: 가이드는 "SQLite·JSON 같은 파일 DB를 저장소에 포함"을 권장. 하지만 Vercel에서는 실행 중에 파일에 쓴 내용이 남지 않음
- After: 좌석·리뷰 샘플은 코드(`js/data.js`)에 넣고, 내가 남긴 리뷰·체크인은 각자 브라우저(localStorage)에 저장
- 이유: 발표 날 300~400명이 동시에 접속해도 서로 영향이 없고, 외부 DB 없이도 "평가가 바로 추천에 반영"되는 흐름을 보여 줄 수 있음
- 검증: 리뷰를 넣으면 점수가 바뀌는지 테스트 (고장 1건 → 그 자리 수리 중·추천 제외, 불만 3건 → 자동 접수·30점 감점)

### 10/03 · index.html 더블클릭으로도 열리게 (빌드팀)
- Before: 파일을 나눌 때 흔히 쓰는 방식(`import`/`export`, JSON 파일 불러오기)은 index.html을 더블클릭하면 브라우저 보안 때문에 동작하지 않음
- After: 일반 `<script>`를 순서대로 불러오고, 데이터는 JS 파일 안에 넣음
- 이유: 심사 때 코드를 내려받아 바로 실행할 수 있어야 함
- 검증: 파일을 직접 열어(file://) 홈 화면, 체크인, 이용 종료, 화면 이동, 초기화가 오류 없이 동작하는지 확인

### 10/03 · 좁은 휴대폰에서 추천 이유가 단어 중간에 줄바꿈됨 (빌드팀)
- Before: 360px 화면에서 "듀얼 / 모니터"처럼 단어 중간에서 줄이 바뀜
- After: 추천 이유 하나하나("소음 낮음", "출입구에서 36m")는 줄바꿈되지 않게 묶음
- 검증: 360px·390px 너비에서 화면을 캡처해 다시 확인
